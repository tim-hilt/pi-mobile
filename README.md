# Pi Mobile

Native iOS client for the [pi](https://github.com/badlogic/pi-mono) agent.

| Path               | What                                                        |
| ------------------ | ----------------------------------------------------------- |
| `bridge/`          | Node/TypeScript server + pi extension sharing live sessions |
| `ios/`             | SwiftUI app (Xcode project generated by XcodeGen)           |
| `docs/protocol.md` | Bridge Protocol — the contract between the two              |

## Develop

Bridge (Node 22+):

```sh
npm install        # also installs git hooks
npm test           # vitest
npm run typecheck
```

iOS (Xcode, `brew install xcodegen`):

```sh
cd ios && xcodegen generate   # after editing project.yml
xcodebuild test -scheme PiMobile -destination 'platform=iOS Simulator,name=iPhone 18 Pro'
```

## Share pi sessions

Every interactive pi shares its session with the bridge; the app lists and joins them. Build the bridge and load the extension in every pi:

```sh
npm run build -w bridge
# ~/.pi/agent/settings.json: "extensions": ["<this repo>/bridge/src/shareExtension.ts"]
```

The first pi starts the bridge (detached, logs to `~/.pi/agent/bridge.log`), configured in `~/.pi/agent/bridge.json` (`publicUrl`, `port` = 8787, `ntfyTopic`, `ntfyUrl`; see [remote setup](docs/remote-setup.md)). `/show-bridge-qr` in pi shows the QR code the app scans to log in. The token is random per start and never stored or logged; scan again after a restart. To run it by hand instead: `npm start -w bridge`.

Notifications: set `ntfyTopic` to an unguessable topic (and `ntfyUrl` if self-hosting) and subscribe to it in the ntfy iOS app to get a push notification with the last answer when a run settles.

Remote access (Cloudflare Tunnel): see [docs/remote-setup.md](docs/remote-setup.md).

Pre-commit runs Prettier, typecheck, and bridge tests; failure blocks the commit.
